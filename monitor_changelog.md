# monitor.sh — история изменений

Журнал изменений [monitor.sh](./scripts/linux/monitor.sh) (до 3.14.1 жил в конце самого скрипта). Описание секций и флагов — в [monitor_documentation.md](monitor_documentation.md).

## 3.18 — POCO F3 и Evolution X

Исправления для POCO F3 на Evolution X — по исходникам мейнтейнера сборки (PocoF3Releases: дерево alioth, ядро, Parts) и Evolver, проверено пробами на телефоне.
«Температура и троттлинг»: у Xiaomi Thermal HAL нет по замыслу — нагревом управляет `mi_thermald`. Вместо «Thermal HAL не готов» — строка «Охлаждение» с текущим профилем демона («Сбалансированный», «Длительная игра», «Камера»…) и его кодом состояния нагрева, если тот не 0.
«Батарея»: на Qualcomm с топливомером (`power_supply/bms`) знак тока берётся из драйвера («плюс = разряд», как пишет Health HAL alioth) — раньше выводился из статуса, и на зарядке под нагрузкой разряжающаяся батарея показывалась заряжающейся, а при «заряжена» направление было «не определено». Если на зарядке батарея садится — пометка «нагрузка больше зарядки», а оценка времени до полного заряда не выводится.
«Подмена»: статус keybox `CHAIN_INVALID / BAD_SIGNATURE_AT_N` из Evolver до 30.09.2026 (ошибка его проверки, в интерфейсе при этом «Valid») — «не проверен» вместо красного «цепочка недействительна». Новое из обновлённого Evolver: число приложений в целях TrickyStore и когда скачан официальный keybox; срок Canary-отпечатка PIF, «импортирован вручную», «SDK для DroidGuard»; строка «Прил. и игры» (App & game spoofing). Google Фото и Snapchat показываются, только если приложение установлено, — как в Evolver.
Безопасность: фильтр keybox в кэше настроек считал концом значения любую строку вида `…=`, и строка base64 из сертификата без отступа могла пройти во временный файл предзагрузки (на экран не выводилась). Теперь конец значения — только ключ из строчных букв или конец XML.

## 3.17.2

Без изменений в отчёте. «Другие подключения» разделены на сбор и вывод, как «Батарея» и «Сеть» в 3.16: Bluetooth, LE Audio, NFC и оплата, точка доступа, геолокация, USB и UWB собираются своими функциями (`conn_*`), а `check_connections` только печатает их по порядку. «Сеть»: каждый ping ограничен по времени целиком (`timeout`), а не только ожиданием ответа — ping сам разрешает имя google.com, и при медленном DNS это не ограничивалось: на Pixel с VPN и частным DNS строка «Интернет» появлялась через 11 с.

## 3.17.1

Без изменений в отчёте. «Модули LSPosed»: версия и путь каждого модуля берутся из ответа `dumpsys package` регулярным выражением bash, а не через `sed | head` — минус два процесса на модуль (на Pixel 8 Pro с 11 модулями трассировка показывала ~1,5 с на этих вызовах). Если проход прерван (Ctrl+C, завершение `--loop`), фоновые команды останавливаются целиком — вместе с запущенными ими `dumpsys`, `settings` и `ping`; раньше останавливалась только обёртка, а сама команда дорабатывала.

## 3.17

Новая секция «Безопасность» после «Системы» — «Система» стала слишком длинной: сюда переехали обновления (патчи безопасности), статус AVB, SELinux, root и Zygisk, а также новые строки ниже; в «Системе» остались время работы и экрана, часовой пояс, формат часов, ABI и сведения о сборке. Для -d — `security`. «Безопасность»: строки «Отпечаток» и «Лицо» для любого телефона — где сканер (под экраном, в кнопке питания), производитель, класс биометрии по данным Android (сильная — Class 3, слабая — Class 2) и сколько настроено; программное лицо LineageOS / Evolution X помечено «программное (Sense)». Строка «Отпечаток» из «Google Pixel» перенесена сюда. «Хранилище»: «Сборка мусора» — какая доля свободного места на f2fs лежит в чистых сегментах (Pixel 8 Pro — 68%, POCO F3 — 24% со срочной сборкой) и «Обслуживание» — дата последнего обслуживания хранилища Android. С -e там же: «Защита» — CFI, Shadow Call Stack, KASLR, PAC, BTI, MTE (что собрано в ядре и умеет процессор) и «Уязвимости» процессора по данным ядра. Ширина канала Wi-Fi не добавлена: Android её не сообщает.

## 3.16.1

«Сеть»: без curl интернет проверяется TCP-соединением самого bash (1.1.1.1:443, затем 8.8.8.8:443) — раньше на Pixel под VPN (ICMP закрыт) при запуске не из MT Manager, где curl есть только у MT, отчёт писал «интернета нет»; строка — «есть (TCP 1.1.1.1:443; ICMP закрыт)». «Топ процессов»: если к замеру какая-то фоновая команда ещё работала, перед top — пауза 1 с (проба: system_server после пачки dumpsys занят до ~1,3 с); если всё давно готово, паузы нет.

## 3.16 — перестройка ради скорости

Отчёт тот же, строка в строку, — меняется устройство скрипта. Медленные команды (dumpsys, settings, df, ping, CLI LSPosed, logcat) запускаются в фоне сразу после замера загрузки процессора, а секции забирают готовый результат в прежнем порядке. Замеры не искажаются: загрузка процессора меряется до запуска фоновых команд, а перед замером «Топ процессов» скрипт дожидается их окончания. Настройки Android читаются одним `settings list` на пространство вместо отдельного `settings get` на каждый ключ (keybox подмены заменяется на «1» ещё в конвейере — ни во временный файл, ни в память он не попадает). Разделы — одним `df` на все. Чтение `module.prop` и перевод килобайт в «ГБ/МБ» — средствами bash, без запуска sed/head/awk на каждый вызов. «Модули LSPosed»: запросы по модулям идут параллельно, а APK не разбирается, если описание и API уже есть в кэше менеджера. Пинги трёх хостов идут одновременно (на Pixel при закрытом ICMP было три секунды ожидания подряд). Секции «Батарея» и «Сеть» разделены на сбор данных и вывод: каждая строка собирается своей функцией. Если скрипт запущен через `sh`, bash ищется ещё и в `/system_ext/bin` (есть в Evolution X). Для разработки — `tests/monitor/regress.sh`: сравнивает вывод двух версий на моках обоих телефонов с обычным и BWK awk.

## 3.15.5

«Батарея»: «Максимум 80%» на Pixel 8 Pro теперь определяется (берётся из BatteryService — узел ядра пишет код 4), а на упоре в лимит — «зарядка остановлена (возобновится ниже 77%)». Battery Share — отдельной строкой с состоянием: «вкл.», «вкл. (ненадолго, автовключение при подключении кабеля)», «выкл. · включится ненадолго при подключении кабеля»; зарядка по USB больше не прячется. Выбранный режим зарядки виден и без кабеля, с подсказкой, когда он сработает (адаптивная — по настройке adaptive_charging_enabled, с ближайшим будильником из AlarmManager). Скорость зарядки в «Питании» — по мощности, как в Android: медленная (< 5 Вт), обычная, быстрая (> 7,5 Вт). «Сеть»: название модема после температуры (Exynos 5300, Snapdragon X55). «Камеры»: модели сенсоров на Xiaomi (POCO F3: Sony IMX582, IMX355, Samsung S5K3T2, S5K5E9). По аудиту: отрицательные температуры от −0,1 до −0,9 °C больше не теряют знак; тест скорости проверяет наличие timeout, ограничен минутой и при неудаче пишет причины; «ZRAM: пусто» для включённого, но пустого zram; блокировка --loop защищена от гонки двух запусков; «Троттлинг: нет (по данным ядра)».

## 3.15.4

Тип памяти на Qualcomm — из device tree (POCO F3: LPDDR5). «Температура и троттлинг» на Snapdragon 870 показывает все три кластера: датчики группы cpu-1 разложены по ядрам (сверено с device tree и sm8250.dtsi), prime-ядро стало «Кластером 3». Тест скорости (--net-speed): актуальный список серверов со своими портами (раньше все шли на 5201 и не отвечали), при «server is busy» пробуется другой порт; скорость — в «Мбит/с», как в строке Wi-Fi. Строка ZRAM подписана явно: «1.8 ГБ данных → 653 МБ в памяти». «Процессор»: большая средняя нагрузка при низкой загрузке CPU больше не даёт «КРИТИЧНО (перегрузка)» — на F3 при зарядке было 18 при 8 ядрах и 31% загрузки; load average считает и задачи, ждущие ввода-вывода.

## 3.15.3

«Система» — строка «Время экрана»: сколько сегодня приложения были на экране и число разблокировок, как в «Цифровом благополучии». Считается по журналу событий UsageStats за сутки; сверено с Wellbeing на Pixel 8 Pro (8:16 против 8:19, 19 разблокировок из 19) и POCO F3 (2:29 против 2:36, 13 из 13).

Новая секция «Камеры» (с -e, после «Графики»): по строке на каждую камеру — роль (основная, широкий угол, телефото, макро, фронтальная), мегапиксели по полному разрешению сенсора, диафрагма, эквивалент 35 мм, кратность телефото и OIS. Перенос длинных строк под колонку значений по ширине терминала (MONITOR_COLS=N — вручную, 0 — выкл.). «Сеть»: строка «Модем» — температура и ограничение из-за нагрева.

## 3.8.1

«Питание» — «USB PD, быстрая · 8.3 В · до 20 Вт»: напряжение с десятыми и единицей в тексте; предел мощности на Pixel из BatteryService.

## 3.8

«Батарея» — строка «Режимы» (максимум 80%, адаптивная зарядка, защита батареи Pixel, энергосбережение, ограничение по температуре) со временем: «полный заряд через ~N», «до 80% через ≈N», «зарядится к чч:мм»; строка «Контроллер» — температура зарядки, USB-порта и ограничение зарядки из-за нагрева. Охлаждение зарядки (chg_mdis, dc_icl) убрано из «Троттлинга», чтобы не дублировать.

## 3.7.2

Объём сброса zram на диск считается по реальному размеру страницы (getconf PAGESIZE), а не по фиксированным 4 КБ — готовность к 16K.

## 3.7.1

«Bootloader» (-e) и «Модем» (Pixel) сверяются с версиями, которые ожидает прошивка (ro.build.expect.*); при расхождении — ВНИМАНИЕ.

## 3.7

Батарея — технология, модель и подлинность (bms/Maxim), даты производства и первого применения (Pixel), температура с десятыми, ёмкость выше паспортной без «калибруется», «н/д» вместо 0 °C/0% при недоступных данных, в -e — внутреннее сопротивление; СИСТЕМА -e — Bootloader и ревизия платы. По аудиту ChatGPT: загрузка CPU «н/д» без /proc/stat, Zygisk не называется сторонним, если настройку Magisk прочитать не удалось, PSI считается и при одной строке, пояснение к MONITOR_SYSROOT.

## 3.6 — по первому запуску на чужом устройстве (Redmi Note 13 Pro 5G)

Скрипт переходит в «/» до запуска — без этого при старте из недоступной root'у папки bash засыпал вывод ошибками getcwd. Проверка «можно ли прочитать» — открытием файла (can_read), а не [ -r ]: на ядрах, где faccessat врёт (KernelSU, Zen-Itsu), пропадали CPU, UFS, ZRAM, PSI и статус AVB. DNS: несколько серверов выводятся через запятую (с 3.1 они склеивались в «10.11.12.1310.11.12.14»).

## 3.5

«Мониторинг» в заголовке и справке; «Настройки VM»; малые и большие ядра Qualcomm с собственными кодами (0x51) показываются настоящими ядрами ARM (у SM8250 — A55); «Энтропия» — фиксированные 256 распознаются по poolsize, а не по версии ядра (новый RNG перенесён и в 4.19, и в 5.4).

## 3.4

Секция «ПАМЯТЬ» — тип памяти, доступно и кэш, zram со сжатием и алгоритмом, подкачка и сброс на диск (writeback), давление PSI, выгрузки lmkd, настройки vm в -e; статус — худшее из «занято %» и давления. Список секций в -d: порядок как в обычном проходе, заголовки с переменными раскрываются («МОДУЛИ MAGISK»), секция модулей теперь называется modules. ZRAM суммируется по всем активным устройствам (zram0 + добавленный zram1).

## 3.3

«Перегрев» вместо «Термостатус» (значения: нет / лёгкий / …); пробный запуск -d [секции]: секции находятся сами по вызову section в коде, выбор через запятую или all, код выхода — итог выбранных секций.

## 3.2

«Ср. нагрузка» (load average за 1/5/15 мин) отдельной строкой, подсказка iperf3 — серой строкой в секции «СЕТЬ», топ процессов в общей колонке с подписью «PID N», «Чип защиты», «Время работы» вместо «Аптайм».

## 3.1 — косметика, отдельные блоки
Отступ перед двоеточием во всех строках, «Статус AVB»; кластеры CPU с типом ядер из /proc/cpuinfo и общим регулятором; русские подписи температур; LTPO по драйверу панели Pixel (panel_idle / min_vrefresh), запасной путь — dumpsys display; VPN поверх Wi-Fi определяется по транспортам VPN-сети, а не по первой сети в списке; топ процессов «PID : имя · CPU · ОЗУ МБ»; «Защитный чип»; модули — заголовок по типу root, статусы, описания; ядро — сборщик, компилятор/линкер, флаги и дата сборки, страница, модули.

## 3.0 — относительно v2

Данные: износ UFS (health_descriptor — папка, версия из specification_version), Zygisk через magisk --sqlite + zygote64, TPU/Titan M2 по реальным путям, честный Verified Boot (ядро против свойств, ловит подмену), Thermal Status из Thermal HAL, датчики CPU из зон ядра (Qualcomm без HAL), троттлинг по охлаждающим устройствам, частоты по кластерам, DNS/Wi-Fi из dumpsys connectivity, SIM по gsm.sim.state, system-as-root и /mnt/vendor/persist, модель Mali из gpuinfo, тип ядра по версии, энтропия ≥5.18, аптайм из /proc. Скорость: getprop и dumpsys thermalservice — по одному вызову за проход (кэши v2 жили в подоболочках и не работали), ping — одна серия на хост. Безопасность: lock в /dev (mkdir, без подмены ссылок), без /tmp-файлов, лог без интерпретации \-последовательностей, logcat '*:E' в кавычках, серийник из cmdline маскируется. Удалено: «Play Integrity» (локально не определяется), bootstrap.sh-опечатка.
