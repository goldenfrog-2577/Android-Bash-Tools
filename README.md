# 🐸 Android Bash Tools by GoldenFrog

Набор скриптов для продвинутых пользователей Android: мониторинг железа, установка APK, распаковка архивов, управление Android TV, спасение устройств по OTG и включение IMS на Pixel.

Все скрипты проверены на двух реальных устройствах:

* **Google Pixel 8 Pro** (husky, Tensor G3), Android 17 QPR1
* **POCO F3** (alioth, Snapdragon 870), Evolution X 11.10 на Android 16 QPR2

На других устройствах скрипты работают в «общем» режиме: датчики и пути ищутся по стандартным именам, а то, чего на устройстве нет, просто не выводится.

## ⚠️ Дисклеймер

Использование скриптов осуществляется на свой страх и риск. Автор не несёт ответственности за возможные последствия.

`otg_kit` работает с разделами устройства на низком уровне. Перед использованием стоит понимать, как устроены fastboot, AVB 2.0, динамические разделы и слоты A/B.

## ⚙️ Требования

* Android 11 и выше (API 30+)
* root-доступ: Magisk, KernelSU или APatch
* toybox (есть в любом Android) — внешний busybox не нужен
* терминал: MT Manager, Termux или `adb shell`
* для `monitor.sh` и `otg_kit.sh` нужен **bash** (есть в MT Manager и Termux) — скрипты сами найдут его и перезапустятся в нём, даже если вызвать их через `sh`

## 🛠 Состав инструментов

### 📊 1. [cpu.sh](./scripts/linux/cpu.sh) — живой монитор CPU, GPU и батареи
Обновляемая картина железа в реальном времени. Работает в штатном `/system/bin/sh`.

* **CPU**: загрузка каждого ядра (на Tensor G3 — все 9, включая Cortex-X3), частоты по кластерам, отметка `▼`, если потолок частоты ниже паспортного.
* **Температуры**: по кластерам и GPU — из термозон ядра по именам датчиков, а не по номерам `thermal_zoneN`, которые меняются от прошивки к прошивке. На Pixel добавляется температура корпуса из Thermal HAL.
* **Троттлинг**: по охлаждающим устройствам ядра (`cur_state > 0`) и статусу Thermal HAL.
* **Батарея**: уровень, ток, напряжение, мощность, износ и циклы.
* Заведомо битые показания датчиков (−40 °C и подобные) отбрасываются.

```bash
su -c sh cpu.sh        # обновление каждые 2 секунды
su -c sh cpu.sh 5      # каждые 5 секунд
su -c sh cpu.sh --once # один снимок
```

### 📦 2. [apks.sh](./scripts/linux/apks.sh) — пакетная установка APK и Split APK
* Установка `.apk` и `.apks` (bundletool, SAI): берутся сплиты из `splits/`, установка через `pm install-multiple`.
* Корректно работает с пробелами и спецсимволами в путях и именах.
* Выбор файлов номерами и диапазонами: `1 3 5-7`.
* Одиночные APK передаются в `pm` потоком — не нужно двойное место под тяжёлые файлы.
* Защита от zip-slip: архивы с путями `../`, абсолютными путями или симлинками отклоняются.
* Расшифровка ошибок установки (подпись, архитектура, место, `MISSING_SPLIT` и др.) с советом, что делать.
* Исходные файлы удаляются только по явному согласию.

### 📺 3. [tv_tools.sh](./scripts/linux/tv_tools.sh) — управление Android TV с телефона
Работает через ADB по Wi-Fi, нужен `adb` на телефоне (Termux: `pkg install android-tools`).

* **Подключение**: проверка реального состояния устройства, сопряжение по коду (Android 11+), запоминание последнего IP.
* **Экран**: скриншоты и запись видео — файлы сразу забираются на телефон и удаляются с ТВ.
* **Пульт и ввод текста**.
* **Приложения**: список, запуск, остановка, очистка данных, удаление, установка APK.
* **Файлы**: отправка на ТВ и получение с него.
* **Питание**: перезагрузка (в том числе в recovery/bootloader) и выключение с подтверждением.
* Все вводимые значения проверяются перед отправкой в оболочку ТВ.

```bash
sh tv_tools.sh                  # спросит IP или возьмёт последний
sh tv_tools.sh 192.168.1.50     # сразу подключиться
```

### 🗜️ 4. [unpacker.sh](./scripts/linux/unpacker.sh) — распаковка ZIP-архивов
Быстрая распаковка тяжёлых архивов (OBB, данные приложений) системным `unzip` с прогрессом.

* Выбор нескольких архивов: `1 3 5-7`, Enter — все. Каждый архив распаковывается в свою папку.
* Защита от zip-slip: архив с абсолютными путями, `..` или трюком «запись через симлинк» отклоняется до распаковки.
* Если папка уже есть — выбор: перезаписать, оставить существующие файлы, новая папка или пропустить.
* Проверка свободного места перед распаковкой.
* Режим проверки целостности без распаковки.
* Работает с системным `unzip` (ziptool), Info-ZIP (Termux) и busybox.

```bash
su -c sh unpacker.sh                                # интерактивно
sh unpacker.sh -y "/sdcard/Download/My Game.zip"    # без вопросов
sh unpacker.sh -t /sdcard/Download                  # только проверить архивы
sh unpacker.sh --help                               # все опции
```

### 🔍 5. [monitor.sh](./scripts/linux/monitor.sh) — полный отчёт о состоянии устройства
Разовый или периодический отчёт по всем подсистемам с итоговым статусом ОК / ВНИМАНИЕ / КРИТИЧНО и кодом выхода для автоматизации.

* **Хранилище**: тип и версия UFS, износ по JEDEC, резервные блоки, заполненность `/data`.
* **CPU, GPU, температуры**: частоты по кластерам, датчики, троттлинг, частота обновления экрана.
* **Батарея**: здоровье, ёмкость относительно паспортной, циклы, ток со знаком, мощность.
* **Сеть**: тип подключения (в том числе VPN поверх Wi-Fi или мобильной сети), Wi-Fi, SIM, DNS, задержка.
* **Безопасность**: Verified Boot с обнаружением подмены свойств, Magisk и Zygisk, SELinux; на Pixel — Titan M2, TPU, AOC.
* **Ошибки logcat**: самые шумные теги и реальные падения приложений.

Кроме двух основных устройств, проверен на Redmi Note 13 Pro 5G (Snapdragon 7s Gen 2, KernelSU).

Подробная документация — [здесь](./monitor.md).

### 🧰 6. [otg_kit.sh](./scripts/linux/otg_kit.sh) — OTG Rescue Toolkit
Спасение Android-устройства с другого телефона по OTG-кабелю: bootloop, неудачная прошивка, конфликт модулей Magisk.

* **Все режимы устройства**: система, recovery, sideload, Pixel Rescue, fastboot (bootloader) и fastbootd — меню меняется под режим.
* **Проверка USB**: видно, подключено ли что-то к OTG физически и в каком режиме (ADB, fastboot, EDL 9008, Samsung Download), даже когда adb его не видит. Устройства по Wi-Fi-отладке не принимаются.
* **Несколько устройств**: выбор нужного, все команды адресуются конкретному серийнику.
* **Прошивка образов** с проверкой сигнатуры (`boot`, `vendor_boot`, `vbmeta`, sparse) и опцией «в оба слота».
* **AFE (Anti Flash & Erase)**: запрет прошивки и стирания критических разделов (`abl`, `xbl`, `tz`, `modem`, `persist`, `bootloader`, `radio` и др.).
* **Дамп раздела** с проверкой размера и MD5 и проверкой места перед копированием.
* **Модули Magisk / KernelSU**: отключение и удаление штатными файлами `disable`/`remove` (обратимо), «отключить все», `magisk --remove-modules` для бутлупа.
* **Pixel Rescue**: `adb reboot rescue`, установка OTA через `adb rescue install`.
* **Загрузчик**: unlock, lock и unlock_critical — только после ввода слова-подтверждения; предупреждения для Xiaomi, Pixel и Samsung перед первой опасной операцией.
* **Format Data** через `fastboot -w`, сбор диагностики (logcat, dmesg, ramoops), журнал всех операций.

```bash
su -c sh /sdcard/otg_kit.sh
```

Папка для образов, дампов и логов — `/sdcard/OTG_ToolKit` (меняется переменной `OTG_WORKDIR`).

#### 🪟 Windows-версия
[otg_kit.bat](./scripts/windows/otg_kit.bat) — тот же набор функций для ПК с Windows 10/11. Пути к `adb.exe`, `fastboot.exe` и рабочей папке задаются в [otg_kit.cfg](./scripts/windows/otg_kit.cfg); если adb и fastboot есть в `PATH`, скрипт найдёт их сам. Вместо проверки OTG — проверка через диспетчер устройств Windows: видно телефон без драйвера, EDL 9008 и Samsung Download.

### 📡 7. [volte_vowifi.sh](./scripts/linux/volte_vowifi.sh) — VoLTE, VoWiFi и видеозвонки на Pixel
Включает VoLTE, звонки по Wi-Fi, видеозвонки (ViLTE) и отображение номера телефона на Google Pixel, если оператор или прошивка их не включают.

* **Флаги платформы** `persist.dbg.{volte,vt,wfc}_avail_ovr` — их напрямую читает `ImsManager` в AOSP.
* **Переключатели для каждой SIM** в базе `siminfo` (с Android 8 они хранятся там, а не в `settings`).
* **Номер телефона**: задаётся через `--number`, если SIM и оператор его не отдают.
* **Бэкап и откат**: перед изменениями сохраняется текущее состояние, `restore` возвращает всё как было.
* **Режим `status`**: показать текущее состояние, ничего не меняя.

```bash
su -c sh volte_vowifi.sh                       # применить
su -c sh volte_vowifi.sh status                # посмотреть состояние
su -c sh volte_vowifi.sh --number +7XXXXXXXXXX # с номером
su -c sh volte_vowifi.sh restore               # откатить
```

⚠️ Скрипт не обходит ограничения оператора на стороне сети. Если оператор не регистрирует устройство в IMS, флаги на телефоне этого не изменят. Проверить регистрацию можно в `*#*#4636#*#*` → «Информация о телефоне».

## 🚀 Установка и использование

1. Клонируйте репозиторий или скачайте нужный скрипт:
   ```bash
   git clone https://github.com/goldenfrog-2577/Android-Bash-Tools.git
   ```
2. Положите скрипты на устройство, например в `/sdcard/` или `/data/local/scripts/`.
3. Запускайте через `sh` от root — права на исполнение и конкретный путь к bash не нужны:
   ```bash
   su -c sh /sdcard/monitor.sh
   ```
